# البنية التقنية وقرارات V1

## المكونات

- واجهة HTML/CSS/JavaScript بلا إطار أو اعتماديات متصفح خارجية. العربية RTL، نماذج مسماة، حوار أصلي، حالات فراغ وفشل، تصميم متجاوب، وتقليل الحركة عند طلب المستخدم.
- FastAPI لواجهات JSON والخدمة الثابتة. نقطة دخول `wasla/main.py`، دون استخدام localStorage كمصدر بيانات تشغيلية.
- SQLite/WAL، معاملات ذرية ومفاتيح أجنبية، ترحيل أولي `migrations/001_initial.sql`. قاعدة علائقية على وحدة تخزين دائمة.
- عامل Python منفصل يقرأ أحداث Webhook من قاعدة البيانات. المعالجة داخل معاملة؛ خطأ العملية يعيد المحاولة حتى خمس مرات ثم `dead`.
- حماية الجلسات بالخادم وتخزين بصمة session token فقط، عمر 8 ساعات، token CSRF لكل جلسة. تغيير كلمة المرور أو إيقاف الحساب يلغي جلساته.
- كلمات المرور باستخدام scrypt مع salt عشوائي. لا يوجد حساب افتراضي أو سر ثابت. قواعد معدلات الدخول مخزنة في القاعدة وتنجو من إعادة تشغيل العملية.

## العزل والصلاحيات

كل سجل شركة تشغيلي يحمل tenant_id. تأتي الشركة من جلسة المستخدم؛ لا يقبل الخادم شركة يختارها المتصفح للوصول إلى بياناته. تستعمل الاستعلامات شرط الشركة والتحقق من ملكية الفرصة/المحادثة للموظف، وتتحقق العلاقات العابرة للسجلات داخل النطاق نفسه. قاعدة SQLite لا تقدم RLS؛ العزل في طبقة التطبيق ومفاتيح مركبة واختبارات سلبية. يجب إعادة تطبيقه واختباره عند إضافة أي endpoint.

مدير مقدم الخدمة يرى الطلبات والشركات والمشروعات وإحصاء أخطاء الأحداث، ولا يقرأ محادثات أو عملاء الشركات. مسار دعم بتفويض مؤقت غير منفذ، فلا يوجد تجاوز عام باسم الدعم.

## سير الطلب

التحقق والتطبيع → فحص Idempotency-Key وبصمة محتوى الطلب → حفظ الطلب والمرجع والمسؤول والموافقة والفرصة والتنبيه وسجل التدقيق في معاملة واحدة → إرجاع المرجع. إعادة نفس العملية تُرجع نفس المرجع، وتغيير المحتوى بنفس المعرف يعيد 409. لا يُرسل بريد خارجي؛ التنبيه محفوظ داخل النظام.

قبول عرض نصي ينشئ مشروعًا واحدًا بمراحل. قيمة العرض أو الفرصة ليست إيرادًا. مرجع التحصيل نص إداري وليس تكاملًا مع حساب بنكي أو نظام فواتير.

## سير الأحداث

فحص توقيع HMAC-SHA256 للبايتات الأصلية → حفظ الحدث الخام وبصمته → 200 → عامل المعالجة → مطابقة Phone Number ID بشركة → إنشاء/جلب جهة الاتصال ضمن الشركة → المحادثة والرسالة → وسم الحدث processed.

منع التكرار على مستوى بصمة الحدث ومعرف رسالة المزود. الرسائل غير النصية تظهر كنوع غير مدعوم؛ لا يجري تنزيل أي رابط أو مرفق. الأحداث غير المعروفة تصل لقائمة مراجعة. سجل الأحداث الخام حساس مثل الرسائل ولا يكشف في لوحة مقدم الخدمة. ينبغي ضبط احتفاظه وتشفير القرص قبل تشغيل حقيقي.

## اختيار SQLite وحدوده

اختيار مقصود لنسخة أولى تعمل دون خدمة سحابية أو مفاتيح أو تكلفة فورية؛ مناسب لتجربة صغيرة على عقدة واحدة. كل طلب يستخدم معاملة قصيرة واحدة، وتستعمل القراءة حاليًا BEGIN IMMEDIATE لتبسيط الاتساق؛ هذا يقيد التزامن ولا يُقدَّم كحل واسع النطاق. لا نحدد حدًا عدديًا للشركات أو الرسائل دون قياس.

قبل زيادة الحمل: نقل المخطط إلى PostgreSQL، pool واستعلامات قراءة منفصلة، عزل صفوف كطبقة إضافية، ناقل أعمال متخصص وتحديث فوري وتخزين خاص للمرفقات. لا تستخدم ملفات SQLite على قرص مؤقت أو نسخة لكل replica.

## النموذج

`tenant → users/contacts/opportunities/tasks/channels/conversations/messages/audit`

`request → provider_opportunity + project → milestones`

`sessions → user`؛ `webhook_events` صندوق أحداث متين؛ `notifications` تنبيه داخلي؛ `content` إعدادات الموقع الأساسية؛ `rate_limits` حماية الدخول والنموذج.

## API

الواجهات الفعلية وتعريف تحقق المدخلات في `wasla/main.py`. المسارات تبدأ `/api`، والأخطاء برسالة `detail`. العمليات المعدلة تتطلب JSON وOrigin مطابقًا، والعمليات المحمية تتطلب cookie وX-CSRF-Token. النموذج والملاحظة يتطلبان Idempotency-Key (16–80 حرفًا من الأرقام والحروف وشرطة/شرطة سفلية). لا تتوفر OpenAPI علنية في الإنتاج.
