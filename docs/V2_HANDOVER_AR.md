# تسليم V2 ضمن نطاق الاختبارات المعزولة

تاريخ التحديث: 16 نوفمبر 2026. المرجع: social_api_customer_service_guide_ar.docx.

## القرار الحالي

بناءً على طلب المالك، يؤجل تشغيل فاحص الملفات الحي وربط الحسابات الفعلية وموافقاتها واختبارات الإرسال والاستقبال الحقيقية. لا يشغّل هذا التحديث أيًا منها. تبقى المعاينة مستقلة عن الإنتاج؛ اكتمال الاختبارات المحلية لا يعني اعتماد إطلاق القنوات.

## ما يمكن تشغيله من لوحة المدير

- إنشاء الشركات وحسابات المنصات وإدارة بيانات الربط المشفرة وإعادة التفويض والفصل.
- إعداد ساعات وأيام العمل والإجازات والسعة والموظفين المتاحين وإيقاف الإرسال.
- مراجعة أدلة الاعتماد والوارد والصادر كلًا على حدة.
- تشخيص طوابير الوارد والصادر والمرفقات، ومعالجة الأحداث المستنفدة وتسوية نتائج الإرسال بدليل.
- عرض عدد العناصر المنتظرة والجاهزة للمعالجة وعمر أقدم عنصر جاهز. الحد الحالي خمس دقائق.
- المحاولات المؤجلة لا تظهر كتوقف للعامل؛ إيقاف الإرسال عمدًا لا يخفي النتائج المجهولة أو الأخطاء المستنفدة.

عامل المعاينة يعمل كل دقيقة. مؤشرات الطوابير ليست نبضًا للعامل ولا تثبت تسليم رسالة لدى منصة. يظل فحص الملفات إلزاميًا؛ عدم تهيئة الفاحص لا يؤدي إلى تجاوز فحص المرفقات.

## الاختبار المعزول

الأداة `scripts/benchmark_service.py` تستخدم قاعدة SQLite مؤقتة وبيانات صناعية، وتزيل محددات اتصال قواعد البيانات الخارجية قبل إنشاء القاعدة. تمرر الأحداث عبر واجهة Webhook مع توقيع اختباري، وتعيد كل دفعة مرة ثانية، ثم تعالجها بالتوازي وتتحقق من:

1. تساوي أعداد الأحداث والرسائل والتذاكر مع عدد الرسائل الفريدة.
2. عدم بقاء حدث فاشل أو غير معالج.
3. عدم إنشاء أي نية إرسال خارجي.
4. مطابقة عدد الطلبات والمتراكم في التقرير للسجل.
5. عدم ظهور طلبات الشركة الأولى في تقرير الشركة الثانية.

النتائج محفوظة في `V2_SYNTHETIC_BENCHMARK.json` و`V2_SYNTHETIC_STRESS.json`. الأزمنة محلية وتتأثر بالجهاز وSQLite، ولا تمثل زمن الشبكة أو أداء PostgreSQL/Vercel أو حدود مزود الرسائل. لا تُستخدم كأساس لوعد سعة إنتاجية.

لإعادة الاختبار من المستودع:

```sh
python -m scripts.benchmark_service --messages 1000 --workers 4 --output /tmp/wasla-benchmark.json
python -m scripts.benchmark_service --messages 10000 --workers 8 --output /tmp/wasla-stress.json
```

## النتائج المحلية المسجلة

| المقياس | السيناريو الأول | اختبار الضغط |
|---|---:|---:|
| رسائل فريدة | 1,000 | 10,000 |
| إعادات تسليم | 1,000 | 10,000 |
| عمال متزامنون | 4 | 8 |
| زمن معالجة الطابور | 1.032 ثانية | 24.581 ثانية |
| زمن التقرير | 22.13 مللي ثانية | 156.55 مللي ثانية |
| أحداث فاشلة أو غير معالجة | 0 | 0 |
| رسائل خارجية أُرسلت | 0 | 0 |

نجحت مطابقة الأعداد وعزل الشركتين في السيناريوهين. يعاد سيناريو 1,000 رسالة في CI وتُحفظ نتيجته كأثر مستقل؛ لا تفرض الأداة حد سرعة يعتمد على جهاز بعينه، لكن أي فقد أو تكرار أو خلل عزل يفشل الاختبار.

## سجل البنود المؤجلة والحدود

| البند | الحالة | شرط الاستكمال |
|---|---|---|
| تشغيل الفاحص الحي | مؤجل بطلب المالك | مضيف HTTPS وتعريفات فحص وتحقق ملف سليم/ضار |
| حسابات المنصات وموافقاتها | مؤجل بطلب المالك | أصول حقيقية وصلاحيات واعتماد رسمي |
| إرسال واستقبال حقيقي | مؤجل بطلب المالك | هاتف/حساب اختبار ودليل وارد وصادر وتسليم |
| قياس سعة الإنتاج | لم ينفذ | حجم متوقع وبيئة مماثلة للإنتاج بعد تهيئة القنوات |
| TikTok Messaging | مشروط بالأهلية وعقد المنتج | موافقة الحساب والعقد الرسمي قبل تنفيذ الموصل |
| Snap DM لخدمة العملاء | غير مدعوم في النطاق | لا يقدَّم موصل الملف العام على أنه صندوق رسائل |
| الحجز أو مشغل CRM خارجي | غير محدد | اختيار المنتج وعقوده؛ CRM الداخلي متاح |
| المحو الكامل للشخص والنسخ | خارج تنقيح محتوى التذاكر الحالي | سياسة وإجراء متسق للهوية والموافقات والنسخ |

## التسليم والرجوع

المستودع وفرع المعاينة يحتفظان بالكود وعقود الطلبات والاختبارات. لا يتطلب التشغيل اليومي تعديل الأكواد. راجع `PROVIDER_INTEGRATIONS_AR.md` لخطوات اللوحة، و`V2_GUIDE_IMPLEMENTATION_AR.md` لمصفوفة الفصول، و`V2_OPERATIONS_AR.md` للتشغيل.

عند مشكلة، أوقف الإرسال للشركة من اللوحة مع الحفاظ على الوارد والطوابير. راجع النتائج المجهولة قبل أي تسوية. لا تحذف بيانات أو ترحيلات بغرض الرجوع إلى واجهة أقدم. لا تفعّل الحسابات المؤجلة لمجرد نجاح الاختبارات الصناعية.
