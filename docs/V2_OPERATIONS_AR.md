# تشغيل واستلام Wasla V2

## المعاينة الحالية

- فرع GitHub: `feat/v2-social-service`، PR #26. لا تغيير في production.
- قاعدة Neon: `preview-v2-pr26`، schema version 4، مستقلة عن الرسمية.
- مخزن R2: `wasla-v2-media-preview`، WEUR (تلميح موقع وليس ضمان إقامة بيانات)، private، ربط r2.dev معطل. مفاتيح قراءة/كتابة كائنات مقيدة بهذا المخزن ومضبوطة في Vercel للفرع وحده.
- اختبار فعلي بمحتوى اصطناعي: كتابة/قراءة/حذف ناجحة. لا ملفات عملاء رفعت.
- لا مستخدم إداري مزروع في قاعدة المعاينة. أنشئ مسؤول المعاينة وفق إجراء التهيئة الحالي؛ لا تستخدم حساب الاختبار المحلي كحساب تشغيل.

## بوابة فحص الملفات

نفذ `python -m scripts.media_scanner` عبر خادم ASGI:

```sh
python -m uvicorn scripts.media_scanner:app --host 127.0.0.1 --port 8010 --no-access-log
```

ضعه على مضيف يديره المالك، مع ClamAV/clamd وتعريفات محدثة باستخدام freshclam. اضبط LocalSocket مطابقًا لـ`WASLA_CLAMD_SOCKET`، واجعل `StreamMaxLength` أكبر من 2 MB. لا تفتح TCP الخاص بـclamd للعامة. ضع الوكيل العكسي HTTPS أمام `/scan` وحدد حجمه ووقته ومعدل طلباته. تحتاج الحاوية أو المضيف موارد كافية لمحرك ClamAV؛ لم ينشر مضيف لهذا الغرض في هذا التحديث.

ولّد رمزًا عشوائيًا بطول 32 بايت على الأقل واحفظه في مدير الأسرار باسم `WASLA_MEDIA_SCANNER_TOKEN` في الفاحص وVercel؛ عيّن `WASLA_MEDIA_SCANNER_URL` إلى HTTPS `/scan`. لا تطبع الرمز ولا ترسله عبر المحادثة.

اختبر ملفًا سليمًا وعينة EICAR الرسمية وتعطل clamd والتوقيع/البصمة الخاطئة. الحكم غير الحاسم أو المحرك غير المتاح يمنع الإتاحة. لا توجد عودة تلقائية إلى «سليم».

مرجع البروتوكول: https://docs.clamav.net/manual/Usage/ClamdProtocol.html

## المتطلبات الخارجية الدقيقة

| القناة | المطلوب من مالك الأصل | دليل قبول التشغيل |
|---|---|---|
| WhatsApp | Phone Number ID وWABA وApp Secret وVerify Token ورمز بصلاحيات الأصل | وارد ورد وقالب معتمد ومرفق وتسليم وسحب تفويض |
| Instagram | IG User ID وApp ID/Secret وInstagram Login وApp Review | OAuth رفض/قبول، وارد ورد من حساب خارجي، صورة، تجديد وإلغاء |
| TikTok | Business Messaging approval + business_id + وثائق Authentication وWebhook schema/signature للحساب | إثبات وارد وصادر وحدود 48h/عدد الرسائل ومرفق وسحب تفويض؛ الموصل محجوب حتى ذلك |
| Snapchat | Public Profile ID ورمز وAllowlist ومرجع موافقة الوصول | مزامنة profile/stats؛ لا اختبار DM لخدمة العملاء لأنه غير مدعوم هنا |

يتم إدخال الأسرار في Vercel/مدير الأسرار، وليس في Git أو حقل مرجع الموافقة. سجل مرجع الموافقة نص غير سري فقط. أسماء المتغيرات في `.env.example` وواجهة إعداد الحساب.

## تشغيل العامل والمراقبة

المسار الداخلي الحالي `/api/internal/drain-webhooks` يشغّل الوارد والصادر والوسائط. استخدم عامل الجدولة الموجود مع `WASLA_WORKER_SECRET` وفي بيئة المعاينة اختبره بعنوان المعاينة وسره الصحيحين. لا توجه مهمة production إلى المعاينة. لا تعتبر نجاح GET health دليلًا على اشتراك الحساب أو عمل العامل.

راجع `/api/v2/operations`: dead events وmedia_jobs وunknown/blocked والموعد المستهدف المتأخر. retry يعالج الوارد/ملفًا مستنفدًا ولا يعيد رسالة صادرة مجهولة النتيجة. التسوية تحتاج دليلًا من المزود.

## دورة الاحتفاظ

`GET /api/v2/retention` معاينة فقط. `PUT` يحدد الأيام وحالة التفعيل ومرجع السياسة. `POST /run` يعالج طلبًا مؤهلًا واحدًا. لا تفعل السياسة لمجرد وجود قيمة واجهة افتراضية. الطلب يجب أن يكون مغلقًا/محلولًا، قديمًا، بلا hold أو إرسال معلق/مجهول. يحذف كائنات المرفقات ويُفرغ محتوى الرسائل وpayloads مع بقاء مفاتيح التكرار. الهوية والموافقات وبيانات التقرير الأساسية تبقى؛ لا يوصف ذلك بمحو كامل لبيانات الشخص.

عند إعداد مهمة دورية، شغّلها عبر حساب تشغيل معتمد ونطاق المنشأة، أو أضفها لجدولة التشغيل المراجعة. لم يُفعّل حذف دوري في المعاينة أو الرسمية. لا تحذف كائنات R2 بسياسة عمر عامة تتجاوز holds.

الروابط الموقعة السابقة قد تبقى صالحة حتى 120 ثانية؛ حذف الكائن يلغي وصولها الفعلي. النسخ الاحتياطية تتبع مدة احتفاظها. بعد الاستعادة أعد تطبيق سجل التنقيح الأحدث قبل فتح الخدمة؛ لا تعتبر استعادة قاعدة قديمة إلغاءً لطلب حذف سابق.

## الاستلام والرجوع

1. طبّق الترحيل عبر `python -m wasla.cli init` باتصال البيئة المقصودة؛ لا ترحيل تلقائي داخل الطلبات.
2. شغّل الاختبارات العامة وPostgreSQL والمتصفحات، ثم اختبار الاستعادة إلى قاعدة منفصلة.
3. نفذ اختبارات حية بحسابات اختبار، وسجّل المعرّفات والنتيجة دون أسرار أو نصوص عملاء.
4. فعّل فريقًا محدودًا، راقب الطوابير والتسليم وSLA، ثم اعتمد التوسعة.
5. عند الرجوع أوقف الإرسال مع الاحتفاظ بالوارد والطوابير. انشر V1 السابق دون إسقاط جداول V2. احتفظ بمفتاح تشفير OAuth خارج نسخة قاعدة البيانات.

لا تثبت الاختبارات المحاكية مراجعة المنصات أو سلامة مسح ملفات حقيقية أو جاهزية production.
