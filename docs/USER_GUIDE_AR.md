# دليل المدير والموظف

## مدير مقدم الخدمة

- يدخل من `/login` بالحساب المُنشأ تفاعليًا بواسطة المشغل.
- «طلبات الخدمات»: يعرض المرجع والعميل والخدمة والمسؤول والحالة. «التفاصيل» تعرض الاحتياج والموافقة؛ يضيف نص العرض قبل اختيار «تم إعداد عرض» أو «مقبول».
- قبول الطلب ينشئ مشروعًا بأربع مراحل مرة واحدة. مرجع التحصيل توثيق إداري؛ لا يعتبر قبول العرض سدادًا تلقائيًا.
- «الشركات»: إنشاء مساحة وحساب مدير بكلمة مرور أولية تسلم آمنًا. الحالات: تجهيز، نشط، معلق. التعليق يمنع الوصول المحمي للمساحة.
- «المشروعات»: تحديث التجهيز وربط مساحة الشركة عند الحاجة. يمكن إبقاء مشروع خدمة مستقل دون اشتراك منصة. لكل مرحلة مخرج نصي وحالة وملاحظات.
- «محتوى الموقع»: تعريف الجهة وبريد ورقم وساعات العمل المعتمدة.
- «صحة التشغيل»: أعداد الأحداث والرسائل الفاشلة مستنفدة المحاولات بمعرفاتها، دون محتوى محادثات العملاء.

## مدير الشركة

- يضيف الفريق ويحدد الدور ويوقف الحسابات. لا يستطيع تعطيل نفسه من لوحة الفريق.
- يضيف العملاء بأرقام دولية ووسوم. لا توجد موافقة تسويقية افتراضية؛ توثق بمصدر ونص عند توفر إثباتها، ويمكن تسجيل الانسحاب.
- ينشئ فرصة مرتبطة بعميل، بقيمة وعملة وموعد. يغير المرحلة ويسند المالك. الإغلاق الرابح يحتاج مرجع إثبات والخاسر يحتاج سببًا.
- «المحادثات»: يرى الرسائل الواردة بعد ضبط الاستقبال، ويسند الموظف ويغلق بسبب أو يعيد الفتح. الملاحظات الداخلية لا تصل إلى العميل.
- «القنوات»: يسجل المعرف التقني فقط، ولا يضع أسرارًا أو مفاتيح وصول في الواجهة.
- «المشروعات»: يراجع المخرج ويطلب تعديلًا أو يعتمد تسليمًا.
- «التقارير»: مجاميع تراكمية، تحويل رابح/مغلق، وعملات منفصلة. ليست تقارير تحصيل مالي.

## الموظف والمشرف والأدوار الأخرى

| الدور | النطاق |
|---|---|
| موظف المبيعات | العملاء، فرصه، مهامه، المحادثات المسندة إليه فقط؛ لا تصدير ولا إدارة مستخدمين |
| مشرف الفريق | العملاء والفرص والمحادثات والتوزيع وتقارير الفريق؛ دون تعديل إعدادات القناة أو الفريق |
| مسؤول التسويق | جهات الاتصال وموافقاتها؛ لا حملات في V1 |
| مسؤول الخدمات | مشروعات الشركة ومخرجاتها وطلب تعديل؛ لا اعتماد نهائي ولا محادثات |
| قارئ | التقارير فقط |

اضغط اسمك أعلى الشاشة للوصول إلى إعدادات حسابك وتغيير كلمة المرور. هذه العملية تلغي جميع الجلسات وتطلب الدخول مجددًا.

## حالات الفشل

- نموذج الموقع يحتفظ بالمدخلات داخل sessionStorage في التبويب عند الفشل، ويستخدم معرفًا ثابتًا لإعادة المحاولة. الموافقات لا تعاد تلقائيًا. لا تدخل بيانات حساسة غير ضرورية.
- إعادة نفس الطلب بنفس المعرف تعيد الرقم المرجعي نفسه؛ تغيير محتوى طلب سبق حفظه بنفس المعرف يرفضه النظام لحماية الاتساق.
- الملاحظة غير المحفوظة تبقى في التبويب حتى نجاح حفظها. لا تعرض الواجهة «تم الإرسال» لرسالة خارجية.
- انتهاء الجلسة يتطلب الدخول؛ الأخطاء تظهر برسالة واضحة وتبقى نماذج الحوارات مفتوحة عند الفشل.
